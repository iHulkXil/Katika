# Katika.Bet roadmap

## Sprint sequence

1. **Sprint 1 — Foundation:** Responsive shell, landing page, visual game lobby, placeholder wallet/rewards/leaderboard/profile surfaces, and product documentation.
2. **Sprint 2 — Identity:** Wallet provider research, connection UX, and non-custodial identity states.
3. **Sprint 3 — Game framework:** Game catalog APIs, game detail contracts, and safe session boundaries.
4. **Sprint 4 — Dice:** First game implementation in a controlled development environment.
5. **Sprint 5 — Coin Flip:** Second game implementation and shared game-state patterns.
6. **Sprint 6 — Mines:** Third game implementation, accessibility review, and performance pass.
7. **Sprint 7 — Roulette:** Fourth game implementation and table interaction system.
8. **Sprint 8 — Rewards:** Reward definitions, eligibility rules, and claim UX.
9. **Sprint 9 — Leaderboards:** Periods, rankings, anti-abuse considerations, and transparent empty states.
10. **Sprint 10 — Profile:** Wallet-linked preferences, privacy controls, and account lifecycle.
11. **Sprint 11 — Hardening:** Security review, observability, accessibility, responsive QA, and failure recovery.
12. **Sprint 12 — Release readiness:** Product review, operational runbooks, policy review, staged rollout, and launch decision.

Dates and scope are intentionally not invented. Each sprint must retain the no-real-money and no-unreviewed wagering boundary until product, security, and compliance decisions are complete.
